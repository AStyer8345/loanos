## Self-Serve Tenant Domain Onboarding (post-V1 scaling)

> Decided 2026-04-28 (Adam): manual Resend domain verification for first 1-2 tenants is fine; build self-serve before tenant #3+. Skipping shared-sending-domain option (`@send.loanos.app`) — every LO wants their real domain on outbound.

- \[ \] **Settings page section** — "Email Sending Domain" card. Inputs: domain. Submit button.
- \[ \] **API:** `POST /api/email/domains` → calls Resend `POST /domains` with the LO's domain. Stores Resend `domain_id` on `org_settings`. Returns the DNS records (SPF + 2 DKIM) for the UI to render.
- \[ \] **UI:** displays each DNS record with type/name/value + a Copy button. "Verify" button polls `GET /api/email/domains/[id]/verify`.
- \[ \] **API:** `GET /api/email/domains/[id]/verify` → calls Resend `GET /domains/{id}` → returns `{ status: 'pending'|'verified'|'failed' }`. On verified, sets `org_settings.from_email = {lo_email}@{domain}` (or lets LO pick the local-part) and shows green check.
- \[ \] **Migration:** add `org_settings.resend_domain_id text`, `org_settings.resend_domain_status text`.
- \[ \] **Admin override:** sys-admin page lists all org domains + statuses; can re-trigger verify or delete on tenant offboarding.

> Eliminates the manual Resend-dashboard step. Tenant goes from "I want my own domain" → sending in ~10 min (DNS propagation), zero ops touch.
