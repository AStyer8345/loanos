# LoanOS Audit Report — 2026-03-19

## Critical Issues (fix immediately)

### 1. TodoList component is built but never rendered
`src/components/dashboard/TodoList.tsx` is a complete, working component backed by a real Supabase table (`todo_items`) and a full REST API (`/api/todos`, `/api/todos/[id]`). It is not imported anywhere in the app. Adam has no access to it. Logged in `tasks/todo.md` as Low Priority, but this is a real UX gap — the pipeline dashboard has a "Queue" tab but no to-do input.
**Fix:** Import and render `TodoList` inside `DashboardClient` on the Queue tab.

### 2. Performance page stores data in localStorage
`src/app/dashboard/performance/page.tsx` uses `localStorage` (key: `loanDashboard2026`) for all financial data: loans, OIE entries, next ID. This is device-specific, will be wiped on browser clear, and is invisible on any other device or browser. Seed data (names, amounts) is hard-coded inline with real borrower names: Voelkel, Aguilar, Stackhouse, etc.
**Impact:** Critical for multi-tenancy and any licensing use case. Data is not in Supabase.
**Acknowledged** in `tasks/todo.md` as Medium. Still unresolved.

### 3. chat_sessions RLS policy is `USING (true)`
Flagged in `tasks/todo.md`: `USING (true)` means any authenticated user can read all sessions across all orgs. Multi-tenancy is now live. This is a data leak waiting to happen if a second org is ever added.

### 4. Duplicate formatter functions across 9+ files
`fmtDate`, `fmtCurrency`, `fmtDateOnly` are re-implemented inline in at least 9 files:
- `src/app/dashboard/contacts/page.tsx`
- `src/app/dashboard/loans/page.tsx`
- `src/app/dashboard/emails/unmatched/page.tsx`
- `src/components/dashboard/DashboardClient.tsx`
- `src/components/dashboard/RecentLoans.tsx`
- `src/app/dashboard/marketing/page.tsx`
- `src/app/dashboard/marketing/social/page.tsx`
- `src/app/dashboard/marketing/rate-updates/page.tsx`
- Multiple scenario components

A canonical `src/lib/formatters.ts` already exists and exports all of these. The duplicates diverge subtly — some use `T00:00:00` timezone fix, some don't. This is a maintenance and bug-breeding problem.

## Architecture Notes

### File / folder structure
- Clean Next.js 14 App Router layout. API routes, pages, components, lib, hooks all properly separated.
- Two DnD libraries imported simultaneously in contacts/page.tsx: `@hello-pangea/dnd` AND `@dnd-kit/core` + `@dnd-kit/sortable`. Only one should be active. This doubles bundle size for that page.
- Dead API route: `/api/pipeline/stats` — fully built, functional, but not called anywhere. Dashboard server component (`dashboard/page.tsx`) fetches all data directly.
- `src/lib/stageNormalization.ts` is a partial duplicate of `src/lib/constants/loan-stages.ts`. It has a smaller `STAGE_MAP` and different canonical names. The contacts page imports `normalizeStage` from `stageNormalization.ts` while every other file uses `normalizeToStageKey` from `loan-stages.ts`. Two normalization systems.
- `PipelineCharts.tsx`, `PipelineKPIs.tsx`, `PipelineSummary.tsx`, `RecentActivity.tsx`, `RecentLoans.tsx`, `UrgentFlags.tsx` in `src/components/dashboard/` are all built but none are imported. `DashboardClient.tsx` renders everything inline. These are orphaned components.

### Layer violations
- `DashboardClient.tsx` defines a local `timeAgo()` and `fmtDate()` that duplicate `src/lib/formatters.ts`. The `fmt` alias (`const fmt = fmtCurrency`) is imported from formatters correctly, but date and relative-time helpers are re-written locally.
- `src/app/dashboard/performance/page.tsx` defines its own `fmt`, `fmtK`, `fmtPct` inline, ignoring `formatters.ts` entirely.

## UI/UX Improvements

1. **Stale loans threshold is 3 days** — fires for nearly every active loan not touched on a weekend. Should be 5–7 days to reduce noise.
2. **Dashboard Queue tab shows SmartActionQueue but no way to add manual tasks** — TodoList is built and works but isn't shown.
3. **Mobile nav uses `text-blue-50/90` text color** — inconsistent with the rest of the dark monochromatic system (should be `text-zinc-300` or `text-white/80`).
4. **Performance page is completely isolated from Supabase** — the full loan data is sitting in Supabase, but this page uses hardcoded seed data. A motivated user could see real commission/volume from the Dashboard Pipeline tab, but Performance is fake.
5. **DashboardClient `timeAgo()` is a local copy** of `fmtRelative()` from `formatters.ts` — slightly different output format (`Xd ago` vs `X days`-style). Should use the shared one.
6. **TopNav uses emoji icons** (📊📋👥📧📐📈📢) in the nav items. Given the design-system focus on IBM Plex + Lucide, these feel out of place. Low priority.
7. **Daily Briefing page (`/dashboard/briefing`)** is a standalone page but is also embedded as a tab in DashboardClient. Duplication of UI — two places Adam can access the same thing.

## Simplification Opportunities

1. **Merge `stageNormalization.ts` into `loan-stages.ts`** — two normalization systems for the same thing. Contacts page currently uses `normalizeStage()` (returns `'Closed'`, `'In Process'`, etc.) while all other code uses `normalizeToStageKey()` (returns `StageKey` enum values). Unify to one function.
2. **Delete orphaned dashboard components** — `PipelineCharts.tsx`, `PipelineKPIs.tsx`, `PipelineSummary.tsx`, `RecentActivity.tsx`, `RecentLoans.tsx`, `UrgentFlags.tsx` are not used. Delete or use them.
3. **Delete `/api/pipeline/stats`** — not called anywhere. DashboardClient server component renders everything directly from Supabase.
4. **Remove one DnD library** — contacts/page.tsx imports both `@hello-pangea/dnd` and `@dnd-kit`. The kanban view uses `@hello-pangea/dnd`; the column drag-to-reorder uses `@dnd-kit`. If column reordering is the only `@dnd-kit` usage, pick one library.
5. **Contacts page local formatters** — 4 inline formatter functions that mirror `formatters.ts` exactly. Replace with imports.
6. **DashboardClient is 450+ lines** — the server component (`dashboard/page.tsx`) is also 200 lines. Both could be split: extract urgentFlags/staleLoans logic into a shared lib function.
