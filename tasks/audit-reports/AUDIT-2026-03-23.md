## Critical Issues (fix immediately)

### 1. `outlook_tokens` — RLS enabled, zero policies
- **Impact:** Users cannot read or write their own Outlook connection tokens via the client.
  The Settings → Outlook integration silently fails on token reads because RLS blocks all access.
- **Fix:** Add `user_id`-scoped SELECT/INSERT/UPDATE/DELETE policies. _(Implemented this session — see Completed Fixes.)_

### 2. `automation_logs` — RLS enabled, zero policies
- **Impact:** Automation history is completely invisible to the client (all SELECT → 0 rows).
  Any UI panel that shows automation run history returns empty, giving a false sense of "nothing ran."
- **Fix:** Add org-scoped policies. _(Implemented this session — see Completed Fixes.)_

### 3. Claude model is one version behind
- **Impact:** Every AI call (chat, briefing, milestone agent, outreach, scenario narratives) runs on
  `claude-sonnet-4-5` instead of the latest `claude-sonnet-4-6`. Immediate free quality upgrade.
- **Fix:** 1-line change in `src/lib/anthropic/model.ts`. _(Implemented this session.)_

### 4. Hardcoded personal info in PDF generator
- **File:** `src/app/api/scenarios/generate-pdf/route.ts:327–331`
- **Impact:** If any future LO licenses LoanOS, their PDF will display Adam's name, NMLS, phone, and
  email as fallbacks. Blocks the $97–$397/mo licensing goal.
- **Fix:** Remove the hardcoded string fallbacks; render blank or pull from org_settings only.
  _(Not yet fixed — requires UX decision on blank-vs-default behavior.)_

## Architecture Notes

### What's working well
- Clean Next.js 14 App Router structure with good layer separation
- `src/lib/anthropic/model.ts` as single source of truth for the Claude model string ✅
- `src/lib/anthropic/client.ts` falls back to `user_settings` table — good for multi-tenant ✅
- Supabase migrations are well-organized; 47 applied, named semantically
- Organization-scoped RLS is the norm for all primary tables (contacts, loans, documents, etc.)
- `scoreLoans.ts` / `stageNormalization.ts` logic is properly in `lib/`, not in components

### Issues

#### `loans/[id]/page.tsx` — 2,855 lines
The loan detail page is a monolith. It re-implements drag-and-drop, field editing, party management,
document uploads, activity feed, and email drafts all in one file. Should be split into at least:
- `<LoanHeader />`
- `<LoanParties />`
- `<LoanTimeline />`
- `<LoanDocuments />`
- `<LoanEmailActivity />`

#### `contacts/[id]/ContactRecordView.tsx` — 1,320 lines
Same pattern. Should be broken into sub-components.

#### `arive-webhook/route.ts` re-implements Supabase HTTP
The Arive webhook manually constructs `fetch()` calls with `sbHeaders()` + `sbUpsert()` instead of
using the existing `createServiceClient()`. This creates two code paths for Supabase writes and
makes the webhook harder to maintain.

#### Duplicate unique indexes on `loans.arive_loan_id`
Both `loans_arive_loan_id_key` and `loans_arive_loan_id_unique` exist — identical, redundant.
One was removed this session. _(See Completed Fixes.)_

#### Duplicate indexes on other tables
- `documents`: `documents_loan_id_idx` + `idx_documents_loan_id` (same column)
- `contacts`: `contacts_organization_id_idx` + `idx_contacts_organization_id` (same column)
These waste write overhead. Low priority but worth cleaning up in a future migration.

### Orphan Tables: `challenges`, `kids`, `responses`
These three tables have fully-open `USING (true)` RLS for ALL operations. They appear to be
from an early experiment or different project (quiz/challenge gamification?). They contain
no sensitive data based on schema, but the open policies are a security audit concern.
**Recommendation:** Drop these tables if unused, or lock them down with proper org-based policies.

### Legacy `user_id`-scoped RLS (multi-tenant gap)
`loan_milestone_events`, `loan_status_history`, and `contact_activity` use `loans.user_id = auth.uid()`
instead of org-based checks. When multiple users share an org, they cannot see each other's
milestone events or status history. This will surface as a multi-tenant bug.

### PostgreSQL Functions — Mutable `search_path` (WARN)
7 functions have no `SET search_path = public`:
- `update_scenarios_updated_at`
- `update_updated_at_column`
- `sync_contact_stage_from_loan`
- `update_contact_last_activity`
- `handle_chat_session_updated_at`
- `notify_n8n_contract_received`
- `propagate_loan_update_to_contact_last_touch`
- `notify_n8n_contract`
- `update_updated_at`

Each should have `SET search_path = public` added to prevent search path injection.

### Unindexed Foreign Keys (Performance)
Supabase advisor flagged the following FK columns as missing covering indexes:
- `chat_sessions.user_id`
- `contact_activity.user_id`
- Possibly others in the full advisor output

These are low-priority but can cause slow JOINs at scale.

## UI/UX Improvements

### Split Design System
`globals.css` has two completely separate palette systems:
1. Main dark tactical: `--bg`, `--surface`, `--border`, `--gold`
2. Scenario Builder: `--sc-bg`, `--sc-card`, `--sc-accent` (navy/blue theme)

The Scenario Builder uses a different color language (blue accent vs gold) which creates a jarring
context switch when navigating between the main dashboard and scenarios. Consider unifying or at
least making the transition intentional with a clear visual separator.

### Layout uses Tailwind `bg-zinc-950` instead of `var(--bg)`
`src/app/dashboard/layout.tsx:9` uses `className="min-h-screen bg-zinc-950"` instead of
the design token `bg-[var(--bg)]`. If the dark background ever needs to change, it requires
two edits instead of one. Minor but inconsistent.

### Unused `Inter` font import
`globals.css:1` imports Inter from Google Fonts but Inter is not defined in the Tailwind config
font families and is not used in any CSS rules. This is a wasted network request on every page load.
_(Fixed this session — see Completed Fixes.)_

### Legacy `--accent-light` / `--accent-border` tokens point to blue, not gold
`globals.css:28–29` defines:
```css
--accent-light:  hsla(210, 70%, 60%, 0.12);  /* blue */
--accent-border: hsla(210, 70%, 60%, 0.5);   /* blue */
```
These are `--accent` aliases but use a blue HSL value instead of gold. Any component using
`var(--accent-light)` gets an unexpected blue tint. _(Fixed this session.)_

### No `loading.tsx` files in dashboard pages
The entire dashboard has no `loading.tsx` skeleton screens. All pages show a blank white flash
during server-side data fetching. Low-effort addition that would significantly improve perceived
performance.
