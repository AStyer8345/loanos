# MISMO 3.4 Parser — Design (Spec 2 of Path B, C-fast)

**Date:** 2026-04-22
**Owner:** Adam Styer
**Status:** Draft — awaiting Adam review
**Parent plan:** Scott's Pilot / Uncle Launch (Path B resequenced)

## Purpose

Scott Sears uses Calyx Point, not Arive. Before he can use LoanOS for real pipeline work he needs to get his existing loans into the product. This spec ships a MISMO 3.4 XML importer so Scott exports a 1003 from Point, drops it into LoanOS, and sees the loan in his pipeline.

This is the **C-fast** variant of the full-1003 vision: parse and store pipeline-basics today, archive the raw XML for a later full re-parse (Spec 5, post-launch). Scott is unblocked in 9 days without committing to a 2-3 week full-schema build that would push May 1.

**Blocker status per GOALS.md (Week of 2026-04-20):** FNM 3.4 file import is listed as a Scott blocker under *LoanOS Product*.

## Success criteria

1. Scott can export a 1003 from Calyx Point, click "Import MISMO" on the Pipeline page, drop the file, review an editable preview, and land a new loan + contact in under 60 seconds.
2. Re-importing the same Point file updates the existing loan (matched by Point's file number) rather than duplicating.
3. Re-importing a new loan for the same borrower updates the existing contact (matched by email + last name + property address) rather than duplicating the person.
4. The raw XML is archived in Supabase Storage, tenant-scoped, so Spec 5 can re-parse it for the full 1003 without asking Scott to re-upload.
5. Malformed, wrong-version, or incomplete files are hard-rejected with a clear error. No partial-state rows land in the database.
6. Cross-tenant isolation holds: Scott's session cannot read Adam's `mismo-files` bucket objects, and vice versa.

## Scope

### In scope (C-fast)

- **Format:** MISMO 3.4 XML only. No FNM 3.2 flat file, no MISMO 2.x, no .enc files.
- **Fields parsed and persisted:** 22 pipeline-basics fields across borrower (6), co-borrower (6), subject property (4), and loan terms (6). Full list in § Field Mapping.
- **Match-or-create flow** with editable preview form (Scott can override any parsed field before commit).
- **Raw XML archive** in a new tenant-scoped Supabase Storage bucket.
- **Hard-reject** on malformed/unsupported/incomplete files.
- **Audit trail** via `activity_log` row per successful import.

### Out of scope (deferred to Spec 5, post-launch)

- Income line items, assets, liabilities, REO schedule, declarations, HMDA.
- Bulk import (multi-file upload).
- Export (MISMO from LoanOS → other LOS).
- Automatic re-parse of archived XML when Spec 5 ships — that spec's plan will define migration behavior.
- Dedicated Import nav item (feedback memory: three-pillar rule — Contacts / Pipeline / Drip Campaigns are first-class).
- Other LOS exporters (Encompass, BLN). C-fast is tested against Calyx Point output only; other exporters may work but are not promised.

### Explicit non-goals

- **SSN storage.** LoanOS does not currently store SSN and will not start with this spec. SSN is parsed transiently during preview display only and is never persisted. Match key is email + last name (see § Match and dedupe logic — contact dedupe key revised during plan review after schema check: `contacts` has no `property_address` column, so the originally-proposed property-address tiebreaker is not available).
- **Loan-level dedupe by anything other than Point's file number.** No heuristic dedupe (e.g., "same property in last 90 days") — explicit `loan_number` match or insert.
- **USPS address canonicalization.** Dumb normalized-string equality is enough for Scott's scale.

## Architecture

Four units with a single job each, composed into two API routes and one UI surface.

```
Pipeline page
  └─ "Import MISMO" button (new, sits next to "Add Loan")
         ↓
Upload modal (file drop)
         ↓
POST /api/mismo/parse   ← Node runtime route
  ├─ upload raw file to Supabase Storage (mismo-files/{orgId}/{uuid}.xml)
  ├─ parser.ts: fast-xml-parser → ParsedMismo struct
  ├─ matcher.ts: look up existing contact by email+lastname+property
  ├─ dedupe check: existing loan by (organization_id, loan_number)
  └─ return { parsed, contactMatch, loanMatch, fileUrl }
         ↓
Preview form (editable, pre-filled, match banners)
         ↓
POST /api/mismo/commit  ← Node runtime route
  ├─ upsert contact (update matched row OR insert new)
  ├─ upsert loan (update matched loan_number OR insert new)
  ├─ insert activity_log entry
  └─ return { loanId }
         ↓
Redirect → /dashboard/pipeline/[loanId]
```

### Component inventory

| Component | Location | Responsibility | Dependencies |
|---|---|---|---|
| `parser.ts` | `src/lib/mismo/parser.ts` | Pure function: `parseMismo(xml: string) → ParsedMismo \| ParseError`. Wraps `fast-xml-parser`. Applies field map. No I/O. | `fast-xml-parser` |
| `normalize.ts` | `src/lib/mismo/normalize.ts` | Pure functions: enum mapping, phone/currency/date coercion, address normalization. | none |
| `matcher.ts` | `src/lib/mismo/matcher.ts` | `findContactMatch(parsed, orgId, db)` + `findLoanMatch(parsed, orgId, db)`. Queries Supabase. | Supabase client |
| Parse route | `src/app/api/mismo/parse/route.ts` | Accepts multipart upload. Uploads to Storage. Invokes parser + matcher. Returns JSON. Runtime: Node (needs XML parsing, >2MB body headroom). | parser, matcher, Supabase |
| Commit route | `src/app/api/mismo/commit/route.ts` | Accepts JSON payload. Transactionally upserts contact + loan + activity_log. Returns loan ID. Runtime: Node. | Supabase |
| Upload modal | `src/components/pipeline/MismoImportModal.tsx` | File drop, progress state, preview form, error display. | parse + commit routes |
| "Import MISMO" button | `src/app/dashboard/pipeline/page.tsx` (or existing header component) | Opens the modal. | `MismoImportModal` |

### Why two routes, not one

- **Parse** is cheap and reversible — a file in Storage and zero DB rows. Scott can cancel the preview and nothing persists in the database.
- **Commit** is the irreversible step.

Separating them keeps orphan state contained to Storage (cleaned by the weekly sweep) instead of half-committed rows. It also lets the preview render fast without waiting for DB writes.

## Data model

**Net-new schema — intentionally small.**

### Migration 093

```sql
-- supabase/migrations/093_mismo_file_url.sql
ALTER TABLE loans ADD COLUMN mismo_file_url TEXT;
COMMENT ON COLUMN loans.mismo_file_url IS
  'Path in the mismo-files Storage bucket; populated on MISMO import, null otherwise';
```

### Supabase Storage bucket: `mismo-files`

- **Created via Supabase MCP** at migration time (not in SQL migration — buckets are API-managed).
- **Path convention:** `{organization_id}/{loan_id_or_upload_uuid}.xml`
  - On parse (pre-commit): `{organization_id}/pending-{uuid}.xml`
  - On commit: the file is moved (via Supabase Storage `move`) to `{organization_id}/loan-{loan_id}.xml` and `loans.mismo_file_url` stores that canonical path.
- **RLS policy:** org-scoped. Members of organization X can read/write objects under `X/*` only. Same `get_my_organization_id()` pattern the Spec 1 audit verified on tables.
- **File size cap:** 2MB enforced client-side and server-side.
- **Retention:** indefinite on successful commit (needed for Spec 5 re-parse). Orphan sweep removes `pending-*` objects older than 7 days.

### What does NOT change

- `contacts` and `loans` columns already accommodate every C-fast field (co-borrower fields are denormalized on both tables as of migration 011 + 051).
- No new `mismo_imports` audit table. `activity_log` carries the import record; Storage carries the file.
- No new lookup tables for MISMO enums — normalization is pure functions.

## Field mapping (MISMO → LoanOS)

The logical mapping below is the contract. Exact XPaths are nailed down in the implementation plan against Scott's sanitized Point fixtures (MISMO 3.4 tag nesting is deep and Point has minor quirks).

### Borrower → `contacts`

| LoanOS column | MISMO source (logical) |
|---|---|
| `first_name` | Party[Role=Borrower] → Individual → Name → FirstName |
| `last_name` | … → LastName |
| `email` | … → ContactPoints → Email |
| `phone` | … → ContactPoints → Telephone (prefer Mobile, fall back to Home) |
| `dob` | Individual → BirthDate |
| `mailing_address` | Party → Addresses → Address[Type=Current] |

### Co-borrower → `contacts.co_borrower_*` + `loans.co_borrower_*`

Same six fields, Party[Role=Borrower] with sequence 2. If file has no second borrower, all co-borrower fields remain null.

### Subject property → `loans`

| LoanOS column | MISMO source (logical) |
|---|---|
| `property_address` | Collateral → Subject Property → Address → AddressLineText |
| `property_city` / `property_state` / `property_zip` | same address block |
| `property_type` | PropertyUsageType → normalize to `primary_residence` / `second_home` / `investment` |
| `property_value` | SalesContractAmount (purchase) OR PropertyValueEstimateAmount (refi) |

### Loan terms → `loans`

| LoanOS column | MISMO source (logical) |
|---|---|
| `loan_number` | Loan → LoanIdentifiers → LoanIdentifier[Type=LenderLoan] |
| `loan_amount` | Loan → TermsOfLoan → BaseLoanAmount |
| `loan_purpose` | LoanPurposeType → normalize to `purchase` / `refinance` / `cash_out_refi` |
| `loan_type` | MortgageType → normalize to `conventional` / `fha` / `va` / `usda` |
| `term_months` | LoanAmortizationPeriodCount |
| `estimated_close_date` | ClosingInformation → EstimatedClosingDate (null if absent) |

**Total: 22 persisted fields** (6 borrower + 6 co-borrower + 4 property + 6 loan).

### Normalization rules (centralized in `normalize.ts`, pure, unit-tested)

- **Enums:** MISMO PascalCase → lowercased + underscored. Unknown values → `null` (not thrown).
- **Phone:** strip to digits; reject if not exactly 10 digits after stripping; format `(xxx) xxx-xxxx` on display only.
- **Currency:** MISMO sends decimal strings (`"350000.00"`). Parse to number; reject if `NaN`.
- **Dates:** MISMO uses ISO 8601. Pass through; null on parse failure.
- **Addresses (for match normalization only):** lowercase, strip punctuation, collapse whitespace.

## Match and dedupe logic

Two independent dedupe keys at two different levels.

### Contact dedupe (identity)

**Key:** `lower(email) = X AND lower(last_name) = Y` (scoped to organization_id).

> Revised during plan review 2026-04-22 from the originally-proposed `email + last_name + property_address` key. Reason: `contacts` has no `property_address` column — subject property lives on `loans`. The multi-match preview UI handles the rare case of two contacts sharing the same email+last_name.

- **Single match** → preview shows banner: *"Match found: Jane Doe · existing contact. New loan will be attached. Uncheck to create new contact instead."* Checkbox defaults to "update existing."
- **Multiple matches** (edge case) → radio buttons listing all matches + "create new" option. No default — forces explicit choice.
- **No match** → banner: *"No existing contact matches. A new contact will be created."*

**What gets updated on match:** only fields Scott edited in the preview form. MISMO values Scott did not touch are ignored. This prevents a re-import from silently overwriting Scott's manual edits.

### Loan dedupe (Point's file number)

**Key:** `organization_id = X AND loan_number = Y` (where Y is `LoanIdentifier[Type=LenderLoan]` from the file).

- **Match** → `update` that loan row with fields Scott edited. Activity log: *"MISMO file re-imported for loan #[number] — [N] fields updated."*
- **No match** → `insert` new loan row. Activity log: *"MISMO file imported."*
- **Loan number missing from file** (rare; Point always includes it, other exporters might not) → insert new loan row with `loan_number = null`, display soft warning in preview: *"No loan number in file — this will create a new pipeline row even if you've imported this borrower before. Set manually?"* with an editable `loan_number` field.

## Error handling

| Failure | Scott-facing behavior | Logging |
|---|---|---|
| File isn't XML (wrong type, binary) | Client toast: *"File doesn't look like XML. Export as MISMO 3.4 from Point."* No upload. | Client only |
| File > 2MB | Client toast: *"File too large (max 2MB)."* | Client only |
| XML malformed | Modal error: *"Couldn't read this file — it looks corrupted. Export again from Point."* Storage file deleted. | Server console (Sentry if wired) |
| Not MISMO 3.4 (wrong root, wrong version) | Modal error: *"This doesn't look like a MISMO 3.4 file. Supported: MISMO v3.4. Found: [detected version or 'unknown']."* | Same |
| Missing required fields | Modal error listing each missing field. Storage file deleted. | Same |
| Storage upload failure | Toast: *"Upload failed, try again."* Retry button. | Server log |
| Commit failure after parse | Toast: *"Couldn't save — [reason]."* Form stays, file stays, Scott retries. | Server log |
| Scott cancels preview | Modal closes. Storage file orphaned; sweep cron is a post-launch follow-up, orphans sit harmlessly until then. | None |

**"Required" for C-fast:**
- Borrower last name
- Borrower email OR phone (one of the two)
- Property address (street + city + state + zip, all four)
- Loan amount
- Loan purpose

Any other missing field → persisted as null, no error.

**Error logging target:** `activity_log` captures successful imports only (failures have no loan to attach to). For failed parses, use server-side `console.error` with a structured payload `{ event: "mismo.parse.failure", reason, file_hash, org_id }`. If Sentry is wired pre-launch, point it there. Do not create a new `import_errors` table for beta.

## Testing

### Unit tests

- **Parser** (`tests/mismo/parser.test.ts`): fixture-based. Each fixture in `tests/mismo/fixtures/` has a matching `.expected.json`. Snapshot equality.
- **Matcher** (`tests/mismo/matcher.test.ts`): seeded DB helper. Cases: single match, multi-match, no match, case-insensitive email, whitespace-collapsed address, loan-number match and miss.
- **Normalizer** (`tests/mismo/normalize.test.ts`): pure unit tests on enum mapping, phone, currency, date, address normalization.

### Integration tests

- `POST /api/mismo/parse` — valid file returns 200 with correct payload and Storage object present.
- `POST /api/mismo/commit` — creates expected rows; re-commit with same loan_number updates instead of inserting.
- Error paths: malformed → 400, not-MISMO → 400, missing required → 400 with field list.
- RLS probe (like Spec 1): Adam-session cannot read Scott-org Storage paths.

### Manual smoke

- Scott provides two sanitized Point exports (one purchase, one refi). Fake names, zero SSNs, real structural shape.
- Adam uploads each through the UI; verify pipeline rows.
- Re-upload purchase file; verify update (not duplicate).
- Import a third file for same borrower + different property; verify new loan attached to existing contact.
