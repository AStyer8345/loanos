## Architecture Notes

### `getServiceClient()` is copy-pasted in 7 API routes (not 4 as noted yesterday)
**Files:** `api/chat`, `api/agents/daily-briefing`, `api/agents/milestone`, `api/agents/cd-extraction`, `api/agents/pa-extraction`, `api/contacts/quick-add`, `api/contacts/bulk-action`
All define identical 4-line `getServiceClient()` functions. Should be exported from `src/lib/supabase/server.ts` as `createServiceClient()`. Low urgency — was noted in yesterday's audit, still not fixed. Adding to backlog.

### STAGE_MAP defined in two places
- `src/app/dashboard/page.tsx` — 30-entry inline constant (covers all Arive status variants)
- `src/lib/stageNormalization.ts` — separate utility file that doesn't appear to be imported anywhere
The dashboard page doesn't import from `stageNormalization.ts`. The lib file is dead code or at minimum un-wired. Should consolidate.

### `performance/page.tsx` stores financial data in localStorage — not Supabase
**File:** `src/app/dashboard/performance/page.tsx:19,87–104`
The performance page (loan P&L tracker) persists all loan data to `localStorage` under `loanDashboard2026`. This means:
- Data is device-specific (won't sync between computers)
- Data is wiped on clear browser data
- No multi-user support
This is appropriate for Phase 1 solo use, but needs a Supabase migration before licensing to other LOs. Flag as Phase 3 tech debt.

### Hardcoded n8n instance URL in client-side code
**Files:** `src/app/dashboard/loans/[id]/page.tsx:13`, `src/app/dashboard/automations/page.tsx:235,466,476`
`N8N_BASE = 'https://styer.app.n8n.cloud/webhook'` is hardcoded as a client-side constant in page components. This is fine for personal use but will break for licensed LOs who have their own n8n instances. Should be `NEXT_PUBLIC_N8N_WEBHOOK_BASE` env var. Low urgency for Phase 1–2.

### `useSearchParams()` missing Suspense boundary in Next.js 14
**Files:** `src/app/dashboard/settings/page.tsx:170`, `src/app/dashboard/marketing/page.tsx:1818`
Both components call `useSearchParams()` at the component level without wrapping in `<Suspense>`. In Next.js 14 App Router with SSR, this causes the entire route segment to opt out of static rendering (which is fine given `export const dynamic = 'force-dynamic'` on the dashboard layout). However it will produce a build warning. Not a functional bug in the current setup.

### `supabase/migrations/` numbering is inconsistent
Files 001–015 use 3-digit prefixes, but 016 and 0017 use 4-digit prefixes (`0016_`, `0017_`). This won't cause runtime errors but is cosmetically inconsistent and may affect tooling that relies on lexicographic ordering.
