# LoanOS Audit Report — 2026-03-21

## 🔴 Fixed This Session

### daily-briefing unscoped fallback (`src/app/api/agents/daily-briefing/route.ts`)
**Issue (HIGH — carried from 2026-03-20):** When the agent-secret path failed to resolve an org, the code `console.warn`'d and continued with `organizationId = null`. The `withOrg` helper silently skipped the `.eq()` filter, causing all data queries (stale leads, active loans, realtor touches) to run against the full tables — all orgs.

**Fix applied:** Added a hard null-check after the org lookup. If `organizationId` is null for any reason, the route now returns HTTP 500 and logs an error instead of running unscoped queries.

```typescript
if (!organizationId) {
  console.error('[daily-briefing] Could not resolve org for agent-secret path — aborting')
  return NextResponse.json({ error: 'Could not resolve organization' }, { status: 500 })
}
```

This was the last HIGH-priority security backlog item from recent audits.

### system_prompts RLS — valid
Table exists with proper `UNIQUE (org_id, name)` constraint, FK to `organizations`, and `org_members_system_prompts` RLS policy (ALL operations scoped to `profiles.organization_id = auth.uid()`). The outreach-prompt route's upsert with `onConflict: 'org_id,name'` is correctly structured.

### activity_log in dashboard/page.tsx — safe
The second activity_log query (line 169–183 of `dashboard/page.tsx`) has no explicit `organization_id` filter, but it uses the session-scoped Supabase client (not service client). RLS policy `Users can read own activity` enforces `organization_id = get_my_organization_id()` — so it's correctly scoped at the DB level.

### emails/unmatched page — RLS-scoped, no explicit org filter needed
Client-side Supabase queries for `activity_log`, `loans`, `contacts` all go through the browser session client. RLS enforces isolation. No action needed until multi-tenant edge cases require stricter explicit filtering.

### loan_milestone_events and milestone_communications — not org-filterable
These tables have no `organization_id` column. They can only be scoped by joining through `loans`. In single-tenant mode this is safe. Flagged as a future task for multi-tenant hardening.
