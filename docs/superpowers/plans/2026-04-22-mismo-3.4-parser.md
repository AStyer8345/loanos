# MISMO 3.4 Import — Slim Plan

> **Rewritten 2026-04-23.** The prior 17-task plan over-engineered this. Most of the machinery (regex MISMO parser, org-scoped loan+contact insert routes, `getOrganization` helper, upload modal shell) already exists. The actual gap is ~3 files: an import endpoint that creates both records, a dashboard button+modal, and a smoke test.

**Goal:** Scott Sears uploads a MISMO 3.4 XML from Calyx Point on the `/dashboard/loans` page → contact + loan land in his org → he's redirected to the new loan detail page. Ship before May 1.

**What already exists (do not rebuild):**
- `src/app/api/mismo/parse/route.ts` — regex-based MISMO field extractor. Returns flat `{ borrowerName, propertyAddress, loanAmount, loanType, loanTerm, interestRate, ssnLast4, purchasePrice, propertyTaxes, insurance }`. Good enough for Scott's first file.
- `src/app/api/import/loans/route.ts` — auth'd, org-scoped loan insert with dedup on `loan_number`.
- `src/app/api/import/contacts/route.ts` — auth'd, org-scoped contact insert.
- `src/app/dashboard/scenarios/new/MISMOUpload.tsx` — working upload modal (uses `/api/mismo/parse`). Currently hands parsed fields to ScenarioBuilder.
- `src/lib/getOrganization.ts` — returns `{ organizationId, userId }`.
- `src/app/dashboard/loans/page.tsx` — the pipeline. Has a header area where an upload button fits.

**Tech stack:** No new deps. No new Supabase migrations. No new Storage bucket. Use what's there.

**Branch:** `feat/mismo-3.4-import`. Commit per task.

**Spec reference:** `docs/superpowers/specs/2026-04-22-mismo-3.4-parser-design.md` — logical field mapping still applies. We're implementing a subset: borrower (single), property, loan terms. Co-borrower, RLS probe, re-parse archive, and match-preview UX are deferred until Scott asks.

**What we're NOT doing (and why):**
- No Supabase Storage bucket for raw XML → Scott can re-export from Point if a re-parse is ever needed.
- No editable match/create preview modal → just create, then let Scott edit on the loan detail page. If dupes happen, he deletes one.
- No separate `parse` + `commit` API split → one `/api/mismo/import` route takes the XML, parses it, creates both records in a single request.
- No co-borrower extraction in v1 → Calyx exports may or may not include it; we'll add on first file that needs it.
- No fixture-based snapshot tests → Scott's real file is the only test that matters for the importer. Add snapshot tests when the parser fails on a second format.
- No `fast-xml-parser` dep → existing regex parser works for Calyx's output. Upgrade if it breaks on a real file.

Implementation: port the regex extraction logic from `src/app/api/mismo/parse/route.ts` verbatim, then post-process:
- Split `borrowerName` → `first_name` + `last_name` on last whitespace. If single token, it's last name.
- Parse `propertyAddress` (currently comma-joined `street, city, state, zip`) back into components. Use `extract('CityName')`, `extract('StateCode')`, `extract('PostalCode')` directly instead of reconstructing — cleaner.
- Add an `extract('LoanIdentifier')` / `extract('LenderLoanIdentifier')` for `loan_number` (not currently extracted).
- Never throw — missing/unparseable fields → null. Bad input (no `<` tag, < 50 chars) → return an all-null `ParsedMismo`. The import route handles the "nothing parseable" case.

## Task 2: Import endpoint

**Files:**
- Create: `src/app/api/mismo/import/route.ts`

**Purpose:** Single POST endpoint. Takes the XML file, parses it, creates a contact (or matches existing), creates a loan linked to that contact, returns `{ loan_id, contact_id }`. Org-scoped via `getOrganization()`.

- [ ] **Step 1: Write the route**

```ts
import { NextRequest, NextResponse } from 'next/server'
import { createClient } from '@/lib/supabase/server'
import { getOrganization } from '@/lib/getOrganization'
import { parseMismo } from '@/lib/mismo/parse'
import type { Database } from '@/lib/database.types'

const MAX_FILE_BYTES = 10 * 1024 * 1024
type ContactInsert = Database['public']['Tables']['contacts']['Insert']
type LoanInsert = Database['public']['Tables']['loans']['Insert']

export async function POST(req: NextRequest) {
  let organizationId: string, userId: string
  try {
    const org = await getOrganization()
    organizationId = org.organizationId
    userId = org.userId
  } catch {
    return NextResponse.json({ error: 'Unauthorized' }, { status: 401 })
  }

  const formData = await req.formData()
  const file = formData.get('file') as File | null
  if (!file) return NextResponse.json({ error: 'No file provided' }, { status: 400 })
  if (file.size > MAX_FILE_BYTES) {
    return NextResponse.json({ error: 'File too large. Max 10 MB.' }, { status: 413 })
  }
  if (file.name.toLowerCase().endsWith('.zip')) {
    return NextResponse.json({ error: 'Upload the .xml directly (ZIP not supported yet).' }, { status: 400 })
  }

  const parsed = parseMismo(await file.text())

  // Minimum viable: need at least a last name OR a loan number.
  if (!parsed.borrower.last_name && !parsed.loan.loan_number) {
    return NextResponse.json({
      error: 'Could not extract a borrower name or loan number from this file. Is it a MISMO 3.4 export?',
    }, { status: 422 })
  }

  const supabase = createClient()

  // ── Contact: match on email (if present) OR (last_name + first_name), else create ─
  let contactId: string | null = null
  if (parsed.borrower.email) {
    const { data: match } = await supabase
      .from('contacts')
      .select('id')
      .eq('organization_id', organizationId)
      .ilike('email', parsed.borrower.email)
      .maybeSingle()
    if (match) contactId = match.id
  }
  if (!contactId && parsed.borrower.last_name) {
    const { data: match } = await supabase
      .from('contacts')
      .select('id')
      .eq('organization_id', organizationId)
      .ilike('last_name', parsed.borrower.last_name)
      .ilike('first_name', parsed.borrower.first_name ?? '')
      .maybeSingle()
    if (match) contactId = match.id
  }

  if (!contactId) {
    const contactInsert: Record<string, unknown> = {
      organization_id: organizationId,
      user_id: userId,
      first_name: parsed.borrower.first_name ?? '',
      last_name: parsed.borrower.last_name ?? 'Unknown',
      email: parsed.borrower.email,
      phone: parsed.borrower.phone,
      contact_type: 'borrower',
      stage: 'lead',
      lead_source: 'MISMO Import',
    }
    const { data: created, error } = await supabase
      .from('contacts')
      .insert([Object.fromEntries(
        Object.entries(contactInsert).filter(([, v]) => v !== null && v !== undefined)
      ) as unknown as ContactInsert])
      .select('id')
      .single()
    if (error) {
      return NextResponse.json({ error: `Contact insert failed: ${error.message}` }, { status: 500 })
    }
    contactId = created.id
  }

  // ── Loan: always insert (dedup by loan_number if present) ─
  if (parsed.loan.loan_number) {
    const { data: dupe } = await supabase
      .from('loans')
      .select('id')
      .eq('organization_id', organizationId)
      .eq('loan_number', parsed.loan.loan_number)
      .maybeSingle()
    if (dupe) {
      return NextResponse.json({
        loan_id: dupe.id,
        contact_id: contactId,
        duplicate: true,
      })
    }
  }

  const borrowerDisplayName = [parsed.borrower.first_name, parsed.borrower.last_name]
    .filter(Boolean).join(' ') || null

  const loanInsert: Record<string, unknown> = {
    organization_id: organizationId,
    user_id: userId,
    contact_id: contactId,
    borrower_name: borrowerDisplayName,
    borrower_first_name: parsed.borrower.first_name,
    borrower_last_name: parsed.borrower.last_name,
    borrower_email: parsed.borrower.email,
    borrower_phone: parsed.borrower.phone,
    loan_number: parsed.loan.loan_number,
    loan_amount: parsed.loan.loan_amount,
    loan_type: parsed.loan.loan_type,
    loan_term: parsed.loan.loan_term_months,
    interest_rate: parsed.loan.interest_rate,
    property_address: parsed.property.address,
    property_city: parsed.property.city,
    property_state: parsed.property.state,
    sales_price: parsed.property.purchase_price,
    status: 'lead',
  }

  const { data: loan, error: loanErr } = await supabase
    .from('loans')
    .insert([Object.fromEntries(
      Object.entries(loanInsert).filter(([, v]) => v !== null && v !== undefined)
    ) as unknown as LoanInsert])
    .select('id')
    .single()
  if (loanErr) {
    return NextResponse.json({ error: `Loan insert failed: ${loanErr.message}` }, { status: 500 })
  }

  return NextResponse.json({
    loan_id: loan.id,
    contact_id: contactId,
    duplicate: false,
  })
}
```

**Notes for the implementer:**
- Use existing column names exactly. Cross-check `src/lib/database.types.ts` — `loans.loan_term` (months, not years — existing import route stores `Math.round(months / 12)` which is wrong; we store months directly here). If there's a conflict, match whatever `/api/import/loans/route.ts` does.
- `loans.status` uses values from `src/lib/constants/loan-stages.ts`. `'lead'` is the right default — verify.
- RLS on `loans` + `contacts` is already enforced via existing policies. The `.eq('organization_id', organizationId)` is belt-and-suspenders.
- No transaction across tables (Supabase JS client can't). If loan insert fails after contact was created, the contact stays — that's acceptable for v1 (Scott deletes manually). Log the orphan in the error response if it happens.
