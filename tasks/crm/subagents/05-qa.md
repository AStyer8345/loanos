## VERIFICATION PROTOCOL

### 1. Output Exists and Is Accessible

**Contact/Data verification:**
```sql
-- Confirm data is live and queryable
SELECT id, full_name, email, phone, created_at FROM contacts
ORDER BY created_at DESC LIMIT 5;

-- Confirm migrated contacts are visible to the correct RLS role
-- (Run as authenticated user, not service_role)
SELECT COUNT(*) FROM contacts; -- Should match build report
```

**n8n workflow verification (if workflows were built):**
- Workflow exists at correct ID (check via GET /api/v1/workflows/[ID])
- Workflow is in INACTIVE state (unless spec explicitly said to activate)
- Trigger configuration matches spec (webhook URL, schedule, event type)
- Test execution: trigger the workflow manually in n8n UI if safe to do so with test data

### 2. Functional Test

**Contact import:**
- Pick 3 migrated contacts at random. Verify all key fields are correct against source data.
- Confirm a new contact can be created via LoanOS UI/API without errors

**Pipeline stages:**
- Confirm all status values in loans table are valid enum values
- Confirm a loan can be moved between stages without RLS errors

**n8n automation (if built):**
- Confirm webhook endpoint returns 200 with test payload
- Confirm test run data appears in Supabase as expected
- Confirm no real emails were sent during testing (check n8n execution log)

### 3. Compliance Spot-Check
Top 3 non-negotiables:
- [ ] No contacts accessible to users who shouldn't see them (test Janie's RLS scope)
- [ ] audit_log table has entries for today's changes (timestamp + user_id + action)
- [ ] No lead routing went to Salesforce — all contacts created in LoanOS (verify in Supabase contacts table)

### 4. Regression Check
Confirm existing LoanOS functionality was not broken:
```sql
-- Confirm active loans are still visible
SELECT COUNT(*) FROM loans WHERE status NOT IN ('funded','denied','withdrawn');

-- Confirm existing contacts are intact
SELECT COUNT(*) FROM contacts WHERE created_at < '[MIGRATION_START_DATE]';
```

Check LoanOS app still loads without errors:
- Verify Vercel deployment status (use Vercel MCP: mcp__ffdaa602-...)
- If a new deployment was triggered — confirm it succeeded via list_deployments
