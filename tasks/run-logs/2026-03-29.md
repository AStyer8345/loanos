## LESSONS_LEARNED

- **emails/link route had no org-scoping on service-role mutations** — pattern to watch: any route that (a) authenticates via `createClient().auth.getUser()` directly (instead of `getOrganization()`), and (b) then uses the service role for mutations, is at risk of missing org scoping. `getOrganization()` is the correct pattern — it provides both auth and org context in one call and should be used consistently in all API routes that touch org-scoped data.
