### Hot Leads Scoring — Logic Concern

`dashboard/page.tsx:20` — `scoreNotes()` does pure keyword matching against `contacts.notes`. This means any contact whose notes mention "follow up" (even closed/archived contacts) will surface. There is a stage filter (`Pre-App`, `Lead`, `Interested`, or no stage set) but no recency-weighted score — a contact with a `daysAgo` of 85 and score of 2 ranks the same as one with `daysAgo` of 1 and score of 2. Works at current contact volume but will produce noise as the database grows. Not a bug — flagged for future refinement.

### arive-webhook Dual Code Paths (unchanged)

## Claude API Usage Audit

### ❌ Hardcoded Model String in quick-add — FIXED THIS SESSION

`src/app/api/contacts/quick-add/route.ts` was using a hardcoded `'claude-haiku-4-5'` string — bypassing the `CLAUDE_MODEL` central constant. This was the only route not using the constant. **Fixed: now imports and uses `CLAUDE_MODEL`.**

Note: `CLAUDE_MODEL` is currently set to `'claude-sonnet-4-5'` in `src/lib/anthropic/model.ts`. The quick-add route intentionally used Haiku (faster/cheaper for simple extraction). Now that it uses `CLAUDE_MODEL`, both routes will upgrade together when the constant is updated. This is an acceptable trade-off since Haiku is cheaper but Sonnet produces better extractions for freeform contact input.

### All Other Routes — Confirmed Using CLAUDE_MODEL ✅

`chat`, `daily-briefing`, `milestone`, `generate-narrative`, `parse-statement`, `refi-intake`, `outreach` — all use `CLAUDE_MODEL`. No hardcoded strings elsewhere.

### No Hardcoded API Keys ✅

All API key access goes through `getAnthropicClient()` → reads from `ANTHROPIC_API_KEY` env var or `org_settings.anthropic_api_key` in Supabase.
